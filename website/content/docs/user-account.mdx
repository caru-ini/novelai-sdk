title: User Account
description: Fetch your subscription tier, actual Anlas balance, and Opus usage limit.
---

`client.user` reports the actual state of your account from the NovelAI API.
Unlike [Anlas Calculation](/docs/anlas-calculation), which estimates the cost
of a request before sending it, these values come straight from the server.

## Quick Example

```python
from novelai import NovelAI

with NovelAI() as client:
    sub = client.user.get_subscription()

    print(sub.tier_name)  # "Opus"
    print(sub.active)     # True
    print(sub.anlas)      # 4250

    # Shortcut when you only need the balance
    print(client.user.get_anlas())
```

The async client works the same way:

```python
async with AsyncNovelAI() as client:
    sub = await client.user.get_subscription()
    balance = await client.user.get_anlas()
```

## Subscription Fields

| Attribute | Description |
| --- | --- |
| `tier` / `tier_name` | `0` = Paper, `1` = Tablet, `2` = Scroll, `3` = Opus |
| `active` | Whether the subscription is currently active |
| `expires_at` | Expiry as a Unix timestamp (seconds) |
| `anlas` | Total Anlas balance (subscription + purchased) |
| `training_steps_left` | Balance split into `fixed_training_steps_left` (granted monthly) and `purchased_training_steps` (never expire) |
| `is_opus` | Whether the account is on the Opus tier |
| `perks.unlimited_image_generation` | Whether free image generation (the Opus perk) is granted |
| `usage` | [Opus usage limit](#opus-usage-limit), or `None` when the API reports none |

Purchased Anlas is only consumed after the subscription portion runs out.

## Opus Usage Limit

On Opus, free NovelAI Diffusion V5 generations draw from an allowance that
refills by itself over time. The web UI shows it as "N% of Opus Generations
remaining". `client.user.get_opus_usage()` reports the same state:

```python
with NovelAI() as client:
    usage = client.user.get_opus_usage()  # same as get_subscription().usage

    if usage is not None:
        print(usage.percent)      # 29
        print(usage.is_negative)  # False
```

| Attribute | Description |
| --- | --- |
| `percent` | Allowance left, in percent. Can exceed 100 |
| `purchased_percent` | Extra usage added by Opus Usage Boosts, in percent |
| `is_negative` | Whether the allowance is used up |
| `time_until_next_percent` | Seconds until the allowance is one percent higher. `0` while refilling is paused above the cap |

`usage` is `None` when the API reports no usage limit. The web UI only shows
it on an active Opus subscription.

While `is_negative` is `True`, the web UI prices V5 generations (V5 Full, V5
Full Medium, and V5 Curated) in Anlas even on Opus. To get the same estimate,
pass `is_opus=False` to `calculate_anlas()` for those models until the
allowance refills.

The fields mirror `usagelimit.Status` in NovelAI's
[OpenAPI schema](https://image.novelai.net/docs/doc.json). The SDK reports
them as they are and does not estimate how much a generation consumes.

## Notes

- `get_subscription()`, `get_anlas()`, and `get_opus_usage()` each send one request to
  `/user/subscription`. Keep the `Subscription` object around when you need
  several fields instead of calling them repeatedly.
